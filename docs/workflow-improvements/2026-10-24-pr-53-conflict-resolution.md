## Improvements

1. **Preflight fixture capabilities before the first full bridge suite.** The initial full run spent 90.899 s waiting on a Goal RPC that its comment fixture could not answer; that failed invocation cost 307 s, and the repair triggered a 102 s focused retry. For cases that add a new RPC assertion, have the fixture preparation step execute a short capability probe against the exact fixture path and report unsupported RPCs before the full suite. Verify impact by checking that a deliberately mismatched fixture fails in setup within seconds and that the normal case still runs through the real CLI/XPC path.
2. **Surface the first failing UI assertion and fixture command output in the host runner summary.** Nine focused Tart retries used 2,024 s of runner wall time before the passing attempt. Failures moved among Goal-state assertions and fixture CLI commands, while the useful messages were buried in per-run `ui-test.log` files. Extend the host Tart runner's failure summary to print the selected case's first XCTest failure with the associated CLI argv, exit code, and captured stderr when present. Verify impact by causing one focused assertion and one fixture-command failure and confirming the host output identifies each without opening the VM artifact by hand.
3. **Measure Tart setup phases before optimizing them.** The ten attempts consumed 2,343 s runner wall time while XCTest selected-case durations totaled 657.240 s, a roughly 1,686 s difference. The current artifacts retain each run's start/exit and XCTest timing but not separate VM boot, snapshot transfer, build, or cleanup durations, so the dominant setup step is unknown. Add phase timestamps to the verified producing component, `scripts/test-ui-tart.sh`, for VM startup, source transfer, build, XCTest, and teardown; compare the phase totals with artifact start/exit times on the next focused run. Use that measurement to target repeated setup rather than changing required verification scope.
