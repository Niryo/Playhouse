## Improvements

1. **Centralize provider fixture ownership setup.** All four new stop cases initially waited about 15s each for a ready marker because their executable override lacked its matching provider ownership marker: **61.047s, 23.7%** of the failed full run's 258.026s case time. Their final-run combined time was 4.845s after repair. Put marker creation/validation and the provider-specific executable override in one bridge-test fixture helper, then use that helper for new native-provider cases. Verify by running a new Codex and Claude fixture case through the helper and checking that the selected fixture reaches its ready marker, while a missing or wrong marker fails immediately with a direct error.
2. **Reuse assertions for natural turn completion and optional task fields.** The first focused retry's four cases finished in 5.125s but failed on two assumptions: `statusMessage` was omitted when nil, and a successful turn without an explicit outcome returned to Waiting Response. Existing bridge contracts already express the latter state. Add a small bridge-test assertion helper for a no-outcome completed task that checks Waiting Response and uses optional-field access for `statusMessage`; use it in provider stop cases. Verify that a new no-outcome case passes for both providers and that an explicit unexpected status still fails.
3. **Retain the runner's phase timing beside each bridge log.** `scripts/test-e2e.sh` prints phase and total durations, while its saved `bridge-tests.log` retains only case output. This leaves the failed focused run's build/setup duration and the active-work share of the 7m39s and 4m21s retry intervals unavailable in this analysis. Save the already emitted phase lines, UTC phase timestamps, and run result to a sibling timing file under the same `/tmp/stationai-bridge.*` artifact directory. Verify that a run artifact alone yields static, build, fixture, and cases durations plus total, and that those durations reconcile with elapsed wall time. This adds retention to an existing producer rather than a new event stream.

Raw phase output for every run is inaccessible to this report, while the bridge artifact does not retain it. Exact task start/end and active agent time would require task activity timestamps and edit/review event timing, which were not supplied here.
