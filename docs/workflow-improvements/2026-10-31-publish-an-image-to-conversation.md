## Improvements

1. **Check the known harness-hazard list before deep bundle-identity debugging.** Blocker #1 made all 93 cases fail in `setUp`, and the exact diagnosis plus the exact fix already existed in the user's auto-memory (`playhouse-bridge-socket-env-leak`, `modified: 2026-10-31T08:13:14Z`, written by a different session) while this worktree lacked the code fix. It was resolved in one edit the moment the note surfaced, after the agent had probed bundle identity, DEBUG flags, `Info.plist` sections and built throwaway probe binaries, and had already handed it back to the user as an unresolved blocker. Both of this task's blockers (socket env leak; `Task.detached` dropping request env) are *environment-propagation* defects, and both are now documented in memory. Action: add a short "known harness hazards" checklist to `.agents/skills/code-review/SKILL.md` runtime-phase instructions — when every case fails in `setUp`, first print the e2e process environment and confirm `PLAYHOUSE_BRIDGE_SOCKET_PATH`/`PLAYHOUSE_BRIDGE_SERVICE_NAME`/`PLAYHOUSE_DATA_DIRECTORY` are not inherited, before investigating bundle identity; and check project memory notes for the failing symptom before declaring a blocker to the user. Verify: next time a mass-`setUp` failure occurs, the first three tool calls should be the env dump, and resolution should not include probe-binary builds.

2. **Make the blocker fixes land in the harness, not only in memory.** The memory note recorded "fixed on 2026-10-31 in `scripts/test-bridge.py`" ~48 minutes before this worktree's `scripts/test-bridge.py` received the fix (mtime 11:01:24). A per-worktree fix of a *shared harness* defect is invisible to every other worktree until merged. Action: when a fix lands in `scripts/` or the bridge harness to unblock a task, state in the task report that the fix is branch-local and name the branch, so it can be fast-tracked to `master` instead of being rediscovered. Verify: no future task should spend a diagnosis cycle on a harness defect already fixed on another branch.

3. **Prefer a failing-path trace over widening a filter when env does not reach a subprocess.** Blocker #2 took three repair rounds. Round (a) widened only the daemon-side env allowlist and was rejected by the architecture reviewer as a provable no-op, because `PlayhouseCLI.swift`/`DaemonClient.swift` strip env before transmission; round (b) widened both client filters and still failed; only round (c) found that `Task.detached` in `PlayhouseBackgroundOperation.run` drops task-locals and so bypasses `PlayhouseProcessEnvironment.current` entirely for 15 call sites. Each round that touched source forced an e2e rebuild of ~150 s plus a static re-review. Action: before editing an env allowlist, trace the variable end to end from CLI capture through transmission, daemon receipt, and the subprocess spawn site, and confirm which hop actually drops it — `BridgeCore.swift:1739` already shows the capture/restore pattern that round (c) needed. Verify: measure repair rounds per env-propagation defect; this one cost three.

4. **The static-before-runtime ordering earned its cost here — keep it, and keep absolute UI assertions.** Both review rounds caught real defects that runtime would not have surfaced: the sheet's `minHeight 760` exceeded the window's `640` content minimum, and the UI viewer-size assertions were relative (`>` the thumbnail) and would still have passed at the old 600 pt sheet — i.e. the test added for this regression could not detect it. Review wall cost was ~170 s + ~161 s because the three reviewers ran in parallel. Action: when a UI case asserts that something got *bigger*, assert an absolute point threshold derived from the new minimum, not a comparison against the element it replaced. Verify: a UI reviewer REJECT for non-detecting size assertions should not recur on sizing changes.
