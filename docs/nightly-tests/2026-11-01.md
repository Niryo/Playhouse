## Failures in the baseline and their fixes

All 21 failures were root-caused; none was fixed by weakening an assertion, extending a
timeout or removing a check.

### Transcript windowing (#97) — 9 cases

`test_claude_resume_recovers_visible_history`, `test_plan_mode_renders_markdown_in_conversation`,
`test_conversation_steers_and_queues_active_turn`, `test_conversation_serializes_concurrent_sends`,
`test_conversation_sends_image_attachments`, `test_codex_agent_image_published_during_active_turn`,
`test_codex_interrupted_turn_blocks_with_reason_and_can_retry`,
`test_task_outcome_in_progress_drives_continuations_until_blocked`,
`test_claude_answer_stays_final_around_outcome_report`.

Cause: opening a conversation now renders only the newest turn ("Showing latest N of M
messages"); the cases looked for older messages that were not rendered yet.
Fix (test): `revealWholeTranscript()` scrolls up until the whole transcript is shown before the
cases assert on older messages. The product behavior is unchanged.

### Mid-turn history refresh — `test_codex_turn_progress_reaches_other_windows_mid_turn`, `test_codex_pending_question_recovers_after_provider_process_restarts`

Cause: a CLI `conversation history` read during a GUI-held Codex thread resumed the thread on a
second app-server with history's defaults, under the running turn, and a shorter mid-turn
history replaced the shown turn.
Fix (product): `ConversationManager.codexHistory` resolves the shared client that already holds
the thread and reads through it with the new `CodexAppServerClient.readOpenThread(id:)`
(`thread/items/list` only — no resume, and the owner keeps its action handler and goal
observation). `sharedClient(loading:compatibleWith:)` prefers the caller's own client when it
holds the thread, so a window whose app-server runs the turn never reads a stale sibling.
`refreshGoalConversation(keepingShownTurn:)` ignores a shorter history while a provider turn is
active. CLI coverage is not feasible headless (the owner/caller split needs the GUI runtime
client); the paired UI cases cover it — documented exception.

### Standalone chat — 4 cases

- `test_standalone_chat_page_sessions_isolate_context`: the comment popover's arrow never
  submitted a comment on a **user** message (assistant messages worked). Root cause: the user
  bubble's selection hint was a `ZStack` sibling of the bubble; SwiftUI then delivered presses
  to the popover's background but never to its controls. Fix (product): the hint is an overlay
  on the user text view, as assistant blocks already do; the arrow `Button` additionally submits
  through a simultaneous tap gesture (its own action still does not fire there), and
  `addAnnotation` is idempotent so assistant messages add exactly one comment. The chip is
  positioned above the selection's first line. The page separator for an explicit new page is
  asserted once its first message lands (an empty page renders no separator by design).
- `test_standalone_chat_separate_model_and_pages_round_trip`: the classifier decision did not
  refresh the transcript separator. Fix (product): `chat_page_updated` is a history-visible
  update type, and the view refreshes page status on revision changes while idle. The Codex
  fixture no longer replays classifier prompts as chat items. The CLI case asserts the revision
  bump after a held decision (fails without the fix).
- `test_standalone_chat_legacy_hidden_task_migrates`: the seeded legacy store was wiped by the
  v2 lifecycle reset. Fix (test): the seed script writes the `task-lifecycle-v2-reset` marker.
- `test_standalone_chat_claude_fallback_classifier`: send-enabled waits and text-based duplicate
  checks were spurious. Fix (test): waits on real provider state (`fixtureTurnCount`,
  `noTurnIsRunning`), turn-ID based duplicate check, Neptune-specific hold.

### Composer — `test_conversation_composer_rejects_blank_and_supports_live_turn_controls`, `test_standalone_chat_page_sessions_isolate_context`

Cause: macOS automatic quote/dash substitution turned a typed `'` into `’`, so the prompt the
fixture received differed from the typed text. Fix (product): the composer editor disables
automatic quote and dash substitution. The composer case now types
`Use "straight" quotes -- it's literal` and asserts the composer value and saved draft; the CLI
case saves and reads back the same literal; the shared expectation gained the clause.

### Comment annotations — `test_conversation_adds_ordered_text_annotations`

Cause: the arrow click on a user message (above) and the conflict-icon pixel assertions written
for the pre-#108 blue icon. Fix: the orange repair icon is asserted (`orange > 2`, `blue == 0`).

### Workspace changes — `test_task_workspace_changes_group_staged_and_unstaged_diffs`, `test_external_git_edits_and_commit_refresh_workspace_changes`, `test_review_pr_conflicts_probe_and_verify`

Cause: an outer `.accessibilityIdentifier` on the change section replaced its children's
identifiers, and mark-viewed is asynchronous. Fix (product): the section is an accessibility
container; the row button carries the committed/uncommitted value. Fix (test): waits for the
mark-viewed persist; row lookups use the container.

### Clear default parent — `test_default_parent_settings_read_write_clear_and_validation`

Cause: in a path-based `UserDefaults` suite, `removeObject` did not clear a value another
process wrote. Fix (product): clearing writes `""`, which every reader already treats as unset.
The CLI could not reproduce the cross-process case; the existing CLI assertions still cover the
clear path — documented exception.

### Question form — `test_codex_async_questions_render_and_reply_as_followup`

Cause: with the newest-turn window, the pending question form was scrolled out of view. Fix
(product): the transcript scrolls to the latest anchor when a question is pending.

## Product changes visible to users (prominent)

1. The composer no longer substitutes smart quotes or dashes for typed punctuation.
2. Comments can be added on user messages with the popover's arrow button.
3. Clearing the default parent folder works across processes.
4. A CLI history read never disturbs a window's running Codex turn.
5. The transcript keeps the shown turn when a shorter history arrives mid-turn, and scrolls a
   pending question form into view.
6. The chat page separator updates when a page decision resolves.
7. Accessibility: the chat sidebar and workspace change sections are containers; change rows
   expose their committed/uncommitted state as a value.
