## Failures and repairs

### Done archive rows unreachable by accessibility hit testing (product regression from #156)

`test_task_done_preserves_worktree_and_branch` failed every time, alone as well, at
"Scrolling should load older completed tasks into the archive viewport": the older task's row had
loaded and was visible at the bottom of the archive, but XCUITest reported it not hittable.

Evidence, in order:

- A trace showed the row and its first PR chip (`#123`) not hittable, while the second chip
  (`#456`) and every other row were hittable. The blocked area lined up with the board scroll
  view's frame (x 76–960) under the open archive panel; `#456`'s center (x 969.5) is outside it.
- A coordinate click at the row's center opened the task, so mouse input reached the row. The
  failure is in accessibility hit testing (what assistive clients and XCUITest use), not clicks.
- After a search moves the row to the top of the list, the case's later `archiveResult.click()`
  also failed as not hittable, so position in the list does not matter.
- The test runner is not trusted for direct `AXUIElementCopyElementAtPosition` calls
  (`kAXErrorAPIDisabled`), so the element at the point could not be read directly.
- Controls: the last green commit (`e68ab55`, exported with `git archive`) passed on the same VM,
  so this is code, not the VM. Bisecting with exported trees: `db4a873`, `05b3da4`, `2f52075` and
  `26d7db2` (#157) pass, `8035f92` (#156, "Redesign and fix Done button") fails.
- Experiments on HEAD that did not change the outcome, all reverted: replacing the new
  `DoneDropDrawer` with a spacer; replacing `.nativeHelp` with `.help` on the archive row and
  chips; overriding `accessibilityHitTest` in the `.nativeHelp` tooltip view.
- #156 also removed `DragEndEventMonitor`, the board container's `.background` NSView. Adding back
  only a bare zero-size NSView there made the case pass.

Fix: `KanbanBoardView` keeps an empty zero-size `BoardAccessibilityHitTestAnchor` NSView behind
the board. The AppKit mechanism is not confirmed, and the code comment says so and names the
guarding case. `test_done_archive_displays_existing_pull_request_link` now also asserts that both
archive PR links are hittable. With the anchor removed it fails at that assertion; with the anchor
it passes.

User-visible effect: none for mouse users. VoiceOver and other assistive clients can reach the
Done archive's rows and PR links again.

### Background-agent failure poll read a missing element

`test_claude_background_agent_keeps_turn_open_until_resolved` failed with "Failed to get matching
snapshot" on `failedAgentRow.label`. The step log shows the answer landed at 28.8 s, the agent row
was missing for a moment while the activity section folded, and the poll fell through to reading
the missing row's label. That read is a fatal error, so `waitUntil` never retried. The poll now
queries by identifier and label (`label CONTAINS "failed"`, the same expectation) and checks that
the disclosure exists before reading its value. The case passed in focused runs.

The task verifier found the same pattern in `test_conversation_shows_context_compaction`
(`row.label.contains("Completed")` while the turn-end reload briefly removes the row). It has not
failed yet; it got the same predicate-query fix.
