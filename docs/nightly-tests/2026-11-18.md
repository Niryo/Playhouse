## Product inconsistency (not changed; needs a decision)

**The Blocked "switch it back" status and #312's branch adoption contradict each other.**

- `task pr sync` on a worktree switched by hand blocks the task with "Switch it back to '<branch>' and sync
  again." (`PlayhouseWorktreeServices.requireTaskBranchCheckedOut`).
- The board's next pull request read adopts the checked-out branch instead (`BoardPullRequestLifecycle.swift`
  `detectPullRequests`, about lines 446–468): it rewrites the record's branch, clears the PR and moves it to
  past worktrees. Unless `adoptedBranchProblem` objects, nothing ties the two together.
- After adoption the Blocked message is stale. Following it makes detection adopt again, since the checked-out
  branch now differs from the newly recorded one. Not following it lets the next sync and auto-PR run on the
  side branch.
- The architecture reviewer suggests one of two fixes:
  - skip adoption while the task is Blocked for a switched branch (or while it has an open, unmerged PR);
  - or clear or rewrite the Blocked message in the same lock as the adoption.

The UI case now avoids this window rather than asserting either behavior.
