## Failures and repairs

### Runner aborted before reporting totals

`scripts/ui-test-dashboard.py` still rejected batches of more than 8 cases. Since the runner's
default became a single session, its exit 2 ended every full run before the aggregate lines
printed. The stale cap is removed.

### PR link chips lost their 30-point hit target

`test_review_pr_conflicts_probe_and_verify` and `test_task_done_preserves_worktree_and_branch`
measured the PR link at 23 pt tall. #126 had replaced the chip's 30-point frame with
`.contentShape(Capsule())`. Both chips in `KanbanBoardView.swift` (the task card and the Done
archive) now keep a minimum 30 × 30 frame with a rectangular hit shape. The Done archive UI case
now asserts the archive chip's width and height too. That gap was what let the regression
through.

### `ls-remote` expectation in the wrong order

`test_task_pr_conflicts_detect_without_mutation` expected `ref<TAB>sha`, but `git ls-remote`
prints `sha<TAB>ref`. This test defect came in with #123, and the expectation is now corrected.

### Shared fixture leaked an `origin` remote

`test_task_pr_create_skips_unchanged_repositories` found an `origin` remote already on the
shared source fixture. With `continueAfterFailure = false`, a failed assertion stops the case
without running its Swift `defer` blocks, so the previous case's remote cleanup never ran. The
six shared-fixture Git cleanups are now `addTeardownBlock`s, which XCTest runs even after a
failure.

### Ghost workspace entry, and an absence check that could not fail

`test_task_workspace_changes_group_staged_and_unstaged_diffs` still saw the ephemeral file's
entry. The viewed snapshot is saved asynchronously, and the case refreshed before the save
landed. It also asserted absence with `XCTAssertFalse(waitForExistence(...))`, which passes the
moment the element is missing. The case now waits for the CLI `task changes list` to drop the
path, and uses `waitForNonExistence` for this check and for two other absence checks (the
comment field and the diff overlay).

### Bridge daemon never exited when idle

`test_bridge_daemon_starts_on_demand_serves_watchers_and_exits_when_idle` waited for an idle
exit that never came. `DaemonMain.swift` cancelled only `conversation.runtime.subscribe` when a
peer disconnected, so the CPU-usage subscription added in #131 kept running and held the daemon
awake. Every `*.subscribe` stream is now cancelled when its peer goes away. New CLI coverage:
`playhouse conversation cpu-usage [--watch]`, and the daemon lifecycle case now runs a CPU
watcher next to the runtime watcher. The CLI case fails with the fix reverted and passes with
it.

### Answered question card came back during recovery (Claude)

`test_claude_pending_question_recovers_after_provider_process_restarts` expected reopened
history to show older turns. Reopening now pins the newest turn by design, so the case waits for
the newest private-answer message instead. Fixing that exposed a real regression from #133: the
stored-page history path (`storedTranscriptPage`, used when `messageLimit` is given) returned the
saved question directly, which bypassed the rule that hides it while the recovery turn holds the
reservation. It now goes through `visiblePendingUserInputRequest`. The CLI case adds paged
(`--limit 80`) checks for both states, and fails with the fix reverted.

Also, a window that did not send the recovery never brought the question card back after that
recovery died. `refreshGoalConversation` now adopts the saved question from history. Requests
answered in this window are excluded: they are marked when the answer is submitted and unmarked
if the call is rejected or throws.

### Transcript stayed blank above the pinned turn

`test_conversation_sends_image_attachments` never loaded the earlier image turn while scrolling
up, but only when it ran after the Claude case above, which kills the daemon. Older messages are
revealed only after an observed scroll sample arms the reveal. When the latest-turn pin landed
on the offset the transcript already had, no scroll sample fired and the reveal stayed disarmed.
`TaskConversationView` now keeps the last sample in a non-state reference and re-checks the
window top once the pin settles. A temporary trace proved it: the failing setup (y = −24 before
the pin) re-armed after the fix, and the pair passed in that order.

### Pre-existing static gate failure

`check-button-feedback` (inside `scripts/test-e2e.sh`) rejected the "Import Conversation…" menu
button added in #139. It now has `.buttonHoverPointer()` and `.help`.

## Failures in confirmation runs (VM environment)

Neither failure involved code this round changed. Both cleared on a fresh VM boot with no code
change, and the final run passed on that boot with the reviewed tree.

- **Confirmation 1:** `test_task_workspace_changes_group_staged_and_unstaged_diffs` showed
  "Monaco couldn't load this diff: the editor stopped unexpectedly."
  - The VM had been up for 29 hours and was 540 MB into swap.
  - WebKit's GPU process hung on nearly every app launch, about 4 times a minute
    (`GPUProcessProxy::didBecomeUnresponsive`).
  - After three hangs while the diff was loading, WebKit killed the editor's content process
    (`GPUProcessCrashedTooManyTimes`). The case then failed alone as well.
  - After the VM was stopped and rebooted, the case passed.
- **Confirmation 2:** on that first fresh boot, `test_task_pr_create_reports_real_gh_failure`
  failed.
  - The screen recording shows the pointer on the Create PR button in its hover state, but
    AppKit never drew the native tooltip. It failed the same way alone.
  - A second-hover retry in the test helper did not change the outcome, so it was reverted.
  - After another reboot, the tooltip appeared on the first hover, and the case and the final
    full suite passed.

## Open items

- Monaco recovery: when WebKit kills the editor's content process, the host rebuilds the editor,
  but the open diff stays on the error until the user clicks "Reload editor". It should re-request
  the diff once the rebuilt editor is ready, within the existing restart budget. Covering this
  needs a UI case that kills the WebContent process.
- The Tart VM degrades over long uptime: WebKit GPU-process hangs, swap, and one boot where no
  tooltip rendered. Consider rebooting the VM at the start of each nightly round.
- Declare streaming commands in a shared bridge contract instead of relying on the `.subscribe`
  name suffix.
- Add a UI case for the sending window staying open while its recovery fails (the
  unmark-on-failure paths are uncovered).
- The transcript reveal regression is caught only when the image case runs after a case that
  kills the daemon. Consider a direct case.
- Profile the slow cases, starting with the annotations case.
