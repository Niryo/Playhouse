## Product change (visible to users)

**A task that moved to Done while a pull request probe was running no longer raises a GitHub CLI alert on the
board.** Moving a task to Done removes its worktrees. A board probe (`task pr status`) that was already in
flight then failed in `gh`, and the card, still holding its stale Review state, showed "GitHub CLI couldn't
complete the request" on a board that no longer had the card. Evidence from first-run half 2
(`test_review_probe_failure_alerts_only_while_in_review`): `task.pr.status` started 00:46:34 with the task in
Review, `task.move.succeeded` to Done at 00:46:34, `bridge.request.failed task.pr.status` at 00:46:37, alert
on a card-less board (`att2/9B064BF6-….png`).

Fix: `BoardTaskManager.pullRequestStatus` (new, `BoardPullRequestLifecycle.swift`) wraps `reviewPullRequests`.
When the read fails it re-reads the task under the task operation lock and returns no state if the task is
Done and none of its pull-request-linked worktrees is left on disk; every other failure is rethrown. The
`task.pr.status` bridge handler (plain and shared) calls it. `reviewPullRequests` itself is unchanged, because
autopilot reads an empty result as "merged". Consequence for the CLI: `task pr status` of such a Done task
now returns `[]` instead of the GitHub CLI error. Both providers share this path; nothing in it is
provider-specific.
